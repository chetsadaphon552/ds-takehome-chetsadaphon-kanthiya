PROBLEM 1.3 - BLOCKING COMPARISON COUNT AND CONVEXITY

Comparison count
----------------
If block i contains m_i records, comparing every unordered pair inside that
block requires:

    f(m_i) = m_i * (m_i - 1) / 2

The total is sum_i f(m_i), subject to sum_i m_i = n.

Why equal sizes minimize comparisons
------------------------------------
For real x >= 0, f(x) = (x^2 - x) / 2 has second derivative f''(x) = 1 > 0,
so f is strictly convex. Jensen's inequality gives:

    (1/k) * sum_i f(m_i) >= f((sum_i m_i) / k) = f(n/k)

Therefore:

    sum_i f(m_i) >= k * f(n/k)

When n is divisible by k, equality holds exactly when every block has size n/k.
For integer block sizes when n is not divisible by k, the minimum is attained
by sizes differing by at most one. To see this, if a block has size a and
another has size b with a >= b + 2, moving one record from the larger block to
the smaller changes the comparison count by:

    f(a - 1) + f(b + 1) - f(a) - f(b) = b - a + 1 < 0

Thus a minimum cannot have block sizes differing by two or more.

Assessment values
-----------------
For n = 2,000,000 and k = 1,000, every equal block has 2,000 records:

    Within-block comparisons = 1,000 * choose(2,000, 2)
                             = 1,999,000,000

Without blocking:

    All-pairs comparisons = choose(2,000,000, 2)
                          = 1,999,999,000,000

This reduces the candidate comparison count by about a factor of 1,000; it does
not guarantee a particular duplicate-recall rate.

Limitation and mitigation
-------------------------
Blocking misses duplicate records placed in different blocks. This can happen
when records have different keys, spelling/formatting variants, missing values,
or inconsistent entity attributes. Mitigations include using several blocking
keys, normalized names and addresses, phonetic keys, sorted-neighbourhood
blocking, and a second pass that evaluates pairs near block boundaries.
Measure recall on labelled duplicate pairs while monitoring the added candidate
pair count.
